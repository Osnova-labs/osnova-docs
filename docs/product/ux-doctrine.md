# UX-доктрина Reborn

## Информационная архитектура

```text
Workspace
  Проект
    Сессии
    Материалы и артефакты
    Подключённые инструменты
  Менеджер инструментов
  Настройки
```

Проект — главный контейнер пользовательской работы. Сессия — отдельная задача или диалог внутри проекта. Инструмент не становится верхнеуровневым «отделом» только потому, что умеет рисовать собственный экран.

## Единое поле ввода

Поле ввода живёт внутри сессии и принимает цель пользователя. Серверная часть возвращает компактную карту проекта, самостоятельно выбирает и читает подходящие источники, передаёт поток ответа, видимый `AgentPlan`, задания, подтверждения, итог с источниками и созданные Tool артефакты.

Агент вызывает Operation. Он не «рисует картинку» и не «создаёт озвучку» сам: соответствующий Tool выполняет операцию и возвращает кандидаты артефактов.

## Контекст

По умолчанию интерфейс показывает только `Контекст · N`. Полный состав, получатель данных, модель, источники и усечение открываются по запросу. Backend не требует постоянно держать отдельную панель контекста на экране.

## Состояния инструмента

Для пользователя Tool — одна сущность. Технические состояния разделяются в Менеджере инструментов: установлен глобально, подключён к проекту, runtime запущен, dependency отсутствует или runtime деградировал.

## Ручная работа равноправна

У каждого Tool может быть manual view. Поле ввода не монополизирует продукт: пользователь вправе открыть конспект, изменить файл, запустить операцию кнопкой или собрать артефакт вручную.

## Правила будущего фронтенда

- Не повторять на каждом экране объяснение, что такое проект.
- Не занимать рабочую область постоянной инспекцией контекста.
- Не смешивать установку, подключение и запуск инструмента в один тумблер.
- Не скрывать сетевого получателя, риск и стоимость операции.
- Не блокировать проект из-за отсутствия AI, OCI, модели или расширения.
- Theme меняет токены и ресурсы, но не навигацию, permissions или product logic.
